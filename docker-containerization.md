## 3. Введение

### 3.1. Цели и задачи работы

Целью работы являлось исследование и оптимизация производительности СУБД в контейнеризированной среде с использованием инструмента нагрузочного тестирования HammerDB.

Ключевые задачи:
- Выбор и обоснование выбора СУБД
- Установка и настройка СУБД в контейнерах Docker
- Настройка HammerDB для нагрузочного тестирования
- Проведение серии нагрузочных тестов
- Анализ полученных результатов

### 3.2. Краткий обзор выбранных технологий

- **Инструмент нагрузочного тестирования:** HammerDB (версия 6.1.1, tpc.org)
- **СУБД:** PostgreSQL (версия 16, официальные Docker-образы)
- **Среда:** Docker Engine + Docker Compose
- **ОС Хоста:** MacOS 24.6.0 Darwin Kernel Version 24.6.0

### 3.3. Методология

Тесты проводились с использованием стандартного набора TPC-C (TPROC-C) в HammerDB с параметрами:
- Количество виртуальных пользователей (VUs): 8
- Время разгона (Ramp-up): 1 минута
- Длительность теста (Duration): 1 минута
- Количество складов (Warehouses): 10

## 4. Этапы выполнения работы

### 4.1. Этап 1: Выбор и конфигурация средств

#### 4.1.1. Обоснование выбора технологий

- **Docker** был выбран как средство контейнеризации благодаря простоте разворачивания, легкости масштабирования и возможности воспроизводимости конфигурации.
- **PostgreSQL 16** был выбран как СУБД благодаря поддерживаемости HammerDB и актуальности версии.

#### 4.1.2. Конфигурация контейнеров

Для сравнения производительности были созданы два контейнера:

| Параметр | pg-debian | pg-alpine |
|----------|-----------|-----------|
| Базовый образ | postgres:16-bookworm | postgres:16-alpine |
| Версия PostgreSQL | 16.15 (Debian) | 16.x (Alpine) |
| Количество CPU | 2.0 | 2.0 |
| Память | 4 ГБ | 4 ГБ |
| Порт | 5432 | 5433 |
| Volume | pg_debian_data | pg_alpine_data |

#### 4.1.3. Подключение HammerDB

HammerDB (tpcorg/hammerdb) запускался в Docker-контейнере с подключением к PostgreSQL через сеть Docker.

---

### 4.2. Этап 2: Сравнение производительности

#### 4.2.1. Методика тестирования

Для обоих контейнеров выполнялись следующие шаги:
1. Построение схемы TPC-C (`build_schema.tcl`)
2. Запуск теста TPROC-C (`run_tprocc.tcl`)
3. Захват результатов

#### 4.2.2. Результаты тестов

| Метрика | pg-debian (Debian) | pg-alpine (Alpine) |
|---------|-------------------|-------------------|
| Статус | FINISHED SUCCESS | FINISHED SUCCESS |
| DBVersion | PostgreSQL 16.15 (Debian) | PostgreSQL 16.x (Alpine) |
| VUs | 8 | 8 |
| Duration | 1 минута | 1 минута |

> **Примечание:** Для полного сбора метрик TPM (Transactions Per Minute) и NOPM (New Orders Per Minute) необходимо выполнить тесты с большей длительностью и проанализировать логи HammerDB, содержащие итоговые показатели.

---

### 4.3. Этап 3: Оптимизация параметров контейнера

В рамках текущего этапа были зафиксированы базовые конфигурации контейнеров для последующего сравнения:
- 2 CPU / 4 GB RAM для обоих контейнеров
- Одинаковые параметры HammerDB (TPROC-C, 8 VUs, rampup=1m, duration=1m)

Планируется серия тестов с изменением одного параметра за раз:
- vCPU: 1 → 2 → 4
- RAM: 2 → 4 → 8 ГБ
